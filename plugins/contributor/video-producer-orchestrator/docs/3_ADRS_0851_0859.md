**Context:** This document embeds 9 load-bearing architectural decisions for the Video Producer Plugin. These decisions are embedded IN the plugin (not in Corvin-ADR) because the plugin itself IS the specification and teaching material for "how to build plugins."

## ADR-0851: Video Producer Orchestration Architecture

**id:** ADR-0851  
**status:** ACCEPTED  
**date:** 2026-09-13  
**depends_on:** ADR-0314 (Learning Infrastructure), ADR-0532 (OS-Skills), ADR-0690 (Plugin Orchestration)  
**relates_to:** ADR-0852 (Workers), ADR-0853 (Quality Gates), ADR-0854 (Learning)

### Problem
CorvinOS needs self-contained demo videos (1-min, 5-min, 15-min) to teach users the system. Current workflow: manual PowerPoint → TTS → FFmpeg is tedious, error-prone, and produces inconsistent quality. Goal: one-command video generation with auditable quality gates and learning loop.

### Solution
**Hero's Journey Orchestrator:** 5-act narrative engine orchestrates 4 specialized Workers:
1. **SlideGenerator Worker:** Pillow-based slides (design system colors/fonts)
2. **AudioGenerator Worker:** Google Cloud TTS with fallback to Piper
3. **VideoAssembler Worker:** FFmpeg orchestration (concat, scale, encode)
4. **QualityValidator Worker:** 5-component scoring (visual, audio, narrative, accessibility, pacing)

**4-Phase Pipeline:**
1. **DRAFT:** Storyboard → slides → audio (no video yet, fast iteration)
2. **PRODUCTION:** Add video assembly, quality validation (≥75/100)
3. **BROADCAST:** Manual review, YouTube metadata, upload queue
4. **PUBLISHED:** Post-upload analytics tracking

**Audit Trail:** Every decision logged (slide chosen, TTS synthesized, frame rendered, quality scored) → ADR-0314 learning loop → optimizer tunes parameters per user feedback.

### Decision
- ✅ Orchestrator is a Skill 2.0 (pluggable, learnable, versioned)
- ✅ Workers are subprocess-isolated (TTS fails → Piper fallback)
- ✅ Quality scoring is deterministic, auditable (no LLM in loops)
- ✅ 4-phase gates are HARD (DRAFT→PRODUCTION requires score ≥75)
- ✅ Design system locked in code (colors.json, typography.json) — no guessing

### Consequences
- **Upside:** Reproducible videos, learnable tuning, fail-safe fallbacks
- **Downside:** TTS cost (mitigated: on-demand synthesis only, cache TTL 30d)
- **Audit:** Every slide, frame, second of audio is recorded (hash-chained)

### Alternatives Considered
1. **Single LLM-Driven Script:** Risk of hallucination, no guarantees on factuality
2. **Manual Template Library:** Hundreds of templates → impossible to maintain
3. **Decoupled Services:** Loose coupling → debugging nightmares, state inconsistency

**Rejected:** All three. Orchestrator + Workers pattern offers auditability + repeatability + learning.

## ADR-0852: Worker Isolation & Fallback Strategy

**id:** ADR-0852  
**status:** ACCEPTED  
**date:** 2026-09-13  
**depends_on:** ADR-0851  
**relates_to:** ADR-0855 (CI/CD), ADR-0533 (Skill Composition)

### Problem
Monolithic video generation = one failure kills entire job. TTS service down, FFmpeg missing, disk full → full retry.

### Solution
**Isolated Worker Contracts:**
```python
class Worker(Protocol):
    async def execute(self, input: WorkerInput) -> WorkerOutput:
        """Raises WorkerError(code, message, can_retry, fallback_worker)."""
        pass
```

**4 Workers, 4 Isolation Boundaries:**
1. **SlideGenerator** → Pillow (fail-fast on invalid JSON, fallback: text-only slide)
2. **AudioGenerator** → TTS (try Google Cloud, fallback Piper, fallback silence)
3. **VideoAssembler** → FFmpeg (verify codec, verify file size, fallback: frame-per-second export)
4. **QualityValidator** → Pure Python (always succeeds, returns score 0-100)

**Fallback Rules:**
- Slide generation fails → use plain white slide + text overlay
- Audio fails → use silence (0.1 dB noise floor)
- Video assembly fails → export PNG sequence + instructions for manual FFmpeg
- Quality validation NEVER fails (score is 0-100, no exceptions)

### Consequence
- Partial failures produce degraded but usable output
- Audit log shows fallback path taken (transparency)
- User can retry specific step without redoing entire job

## ADR-0853: Quality Gating Framework (DRAFT / PRODUCTION / BROADCAST)

**id:** ADR-0853  
**status:** ACCEPTED  
**date:** 2026-09-13  
**depends_on:** ADR-0851, ADR-0852  
**relates_to:** ADR-0853 (Quality Scorer)

### Problem
Video quality is subjective. How to define "ready for YouTube"?

### Solution
**3-Tier Quality Gates:**

| Gate | Score | Manual Review? | Next Step |
|---|---|---|---|
| **DRAFT** | 0-50 | No | Iterate scripts, TTS tweaks |
| **PRODUCTION** | 50-85 | No | Automated upload queue |
| **BROADCAST** | 85-100 | YES (human) | YouTube publish |

**Quality Score Components (5-point rubric):**
1. **Visual Clarity (0-20):** Slide text readability, color contrast (WCAG AA)
2. **Audio Quality (0-20):** No clipping, proper volume normalization, clear pronunciation
3. **Narrative Flow (0-20):** Pacing matches visual transitions, ADR facts verified
4. **Accessibility (0-20):** Captions present, audio descriptions for diagrams
5. **Technical Specs (0-20):** Codec supported (H.264), bitrate optimal (2-6 Mbps)

**Hard Rules:**
- Score < 50 → DRAFT (must iterate)
- Score 50-85 → PRODUCTION (auto-publish to queue, user can override)
- Score ≥ 85 → BROADCAST (requires human click)
- Never skip a gate (no env var override)

### Consequences
- Consistency across videos (all meet baseline)
- Auditable quality decisions (score + breakdown in audit log)
- Learning loop can tune rubric weights per user feedback

## ADR-0854: Narrative Framework (Hero's Journey + Fact-Checking)

**id:** ADR-0854  
**status:** ACCEPTED  
**date:** 2026-09-13  
**depends_on:** ADR-0851  
**relates_to:** ADR-0625 (Content Validation)

### Problem
Random scripts → random quality. How to structure narrative consistently?

### Solution
**Hero's Journey 5-Act Structure:**
1. **Inciting Incident:** The problem CorvinOS solves
2. **Rising Action:** Core feature walkthrough (3-4 concepts)
3. **Climax:** CorvinOS in action (demo scenario)
4. **Falling Action:** User empowerment (you can do this)
5. **Resolution:** Call-to-action (install, docs, community)

**Template per Duration:**
- **1-min:** Inciting + Climax + Resolution (3 slides, 20s per slide)
- **5-min:** Full 5-act (12 slides, 25s per slide)
- **15-min:** 5-act + deep dives (30 slides, 30s per slide)

**Fact-Checking Pipeline:**
```
Script → Fact Extractor (extract claims)
      → ADR/Docs Cross-Reference (validate against /docs/, /ADRs/)
      → Confidence Score (0-100)
      → If confidence < 75: FLAG FOR REVIEW
```

No hallucinated facts. Every claim tied to a source (ADR, docs file, link).

## ADR-0855: CI/CD & Automated Testing

**id:** ADR-0855  
**status:** ACCEPTED  
**date:** 2026-09-13  
**depends_on:** ADR-0851  
**relates_to:** ADR-0855 (Testing)

### Problem
Manual testing = slow iteration. CI/CD is standard, but video testing is hard (image comparison, audio metrics).

### Solution
**GitHub Actions Pipeline:**
1. **Lint + Type Check** (1m)
   - `pylint src/`
   - `mypy src/`
2. **Unit Tests** (5m)
   - Workers in isolation (mock TTS, mock FFmpeg)
   - Quality scorer (deterministic)
   - 96+ tests, ≥85% coverage
3. **Integration Tests** (10m)
   - Full DRAFT pipeline (storyboard → DRAFT video)
   - Quality gates (DRAFT, PRODUCTION, BROADCAST)
   - Fallback paths (TTS fails → Piper)
4. **E2E Tests** (15m)
   - 1-min video end-to-end (real Google TTS if API key present, else mock)
   - Verify output file exists + has correct codec
   - Verify audit trail (all steps logged)

**Test Infrastructure:**
- `pytest` + `pytest-asyncio` (async workers)
- `pytest-cov` (coverage, fail if <85%)
- `responses` library (mock HTTP requests)
- `ffmpeg-python` (verify output codec without full render)

**Gating Rules:**
- All tests must pass before merge
- If any test >3 standard deviations slower → flag in PR
- Code coverage <85% → block merge

## ADR-0856: Learning Loop Integration (ADR-0314)

**id:** ADR-0856  
**status:** ACCEPTED  
**date:** 2026-09-13  
**depends_on:** ADR-0314 (Learning Infrastructure), ADR-0851  
**relates_to:** ADR-0853 (Quality Gates)

### Problem
Quality gates are static (score < 50 → DRAFT). But what if majority of users want looser gates? How does the plugin learn?

### Solution
**Feedback Loop:**
1. User rates video (⭐☆☆ to ⭐⭐⭐⭐⭐)
2. Plugin emits `VideoFeedbackEvent` (video_id, rating, timestamp, user_id)
3. Learning daemon reads events (daily)
4. Optimizer computes: "users who rate 3+ stars have quality_score ≥ X"
5. Next video's gate threshold is tuned (e.g., 50 → 55 if data says so)
6. Audit log shows: "quality_gate_threshold: 50 → 55 (confidence 0.87)"

**Constraints:**
- Never lower gates below "safety floor" (BROADCAST always requires ≥75)
- Optimizer must cite >= 10 data points before making change
- User can revert tuning (manual gate override with reason)

## ADR-0857: Design System as Code

**id:** ADR-0857  
**status:** ACCEPTED  
**date:** 2026-09-13  
**depends_on:** ADR-0851, ADR-0852  
**relates_to:** ADR-0672 (Plugin Manifest)

### Problem
Designers hand Figma files, developers freestyle colors. Inconsistent branding across videos.

### Solution
**Design System in Code (JSON):**
```json
{
  "colors": {
    "primary": "#2D5F8D",
    "secondary": "#E67E22",
    "accent": "#27AE60",
    "text_dark": "#2C3E50",
    "text_light": "#ECF0F1",
    "bg_light": "#F8F9FA",
    "bg_dark": "#1A1A1A"
  },
  "typography": {
    "heading_font": "Inter Bold",
    "body_font": "Inter Regular",
    "heading_size": 48,
    "body_size": 24
  },
  "layout": {
    "slide_width": 1920,
    "slide_height": 1080,
    "margin": 60,
    "line_spacing": 1.5
  }
}
```

**Validation:**
- Colors must satisfy WCAG AA contrast (text on background)
- Fonts must be licensed for video embedding
- Proportions must match 16:9 (YouTube standard)

**Version Control:**
- `design_system.v1.json` (locked at plugin release)
- Changes require new ADR + version bump

## ADR-0858: YouTube Integration & Analytics

**id:** ADR-0858  
**status:** ACCEPTED  
**date:** 2026-09-13  
**depends_on:** ADR-0851, ADR-0853  
**relates_to:** ADR-0529 (External Service Integration)

### Problem
Video sits in plugin → user doesn't know how to get it to YouTube. No visibility into performance.

### Solution
**3-Step YouTube Flow:**
1. **Authenticate:** User provides YouTube OAuth token (stored in encrypted plugin state)
2. **Upload:** Plugin submits video to YouTube (unlisted first, scheduled publish)
3. **Track:** Daily analytics pull (views, watch time, CTR)

**Upload Metadata:**
```python
{
  "title": "CorvinOS: The 1-Minute Guide",
  "description": "[Generated from ADR-0851 storyboard]\n\nLearn CorvinOS in 1 minute...",
  "tags": ["CorvinOS", "tutorial", "open-source"],
  "category": "Science & Technology",
  "privacy_status": "unlisted",  # Always start unlisted
  "publish_at": "2026-09-20T14:00:00Z"
}
```

**Analytics:**
- Hourly for first 24h (catch problems early)
- Daily thereafter
- Dashboard shows: views, AVD (average view duration), CTR, shares
- If AVD < 30% → flag as "needs editing"

## ADR-0859: Plugin Self-Documentation (BUILDING_PLUGINS.md)

**id:** ADR-0859  
**status:** ACCEPTED  
**date:** 2026-09-13  
**depends_on:** ADR-0851

Plugin is complex. Next developer (or future you) should be able to extend it without PhD.

2. **ARCHITECTURE.md** (system diagram + design decisions)

**Key Principle:** The plugin teaches by example. Every concept has working code.

## Summary: ADR Load-Bearing Constraints

| ADR | Constraint | Enforcement |
|---|---|---|
| 0851 | Orchestrator is only entry point (no direct Worker calls) | Tests verify only TaskManager.submit() calls workers |
| 0852 | Workers never raise unhandled exceptions | Tests verify error handling (fallback logic) |
| 0853 | Quality gates are never skipped (hard DRAFT/PRODUCTION/BROADCAST) | Unit tests + E2E tests verify gate enforcement |
| 0854 | No AI-generated facts without source | Fact-checker fails if confidence < 75 |
| 0855 | Tests run on every commit (no bypass) | GitHub Actions status check required |
| 0856 | Learning loop never changes BROADCAST gate (≥75 floor) | Optimizer code enforces min_threshold = 75 |
| 0857 | Design system JSON is source of truth (no hardcoded colors) | All colors imported from design_system.json |
| 0858 | YouTube tokens are encrypted (never in logs) | Encryption tested, audit logs redacted |
| 0859 | Plugin is self-contained (no external docs required) | All docs embedded, examples runnable |
