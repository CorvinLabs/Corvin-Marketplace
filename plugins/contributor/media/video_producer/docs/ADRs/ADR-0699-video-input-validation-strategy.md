# ADR-0696 — Video Producer Input Validation Strategy

**Status:** Proposed  
**Date:** 2026-09-13  
**Deciders:** Claude Haiku 4.5, Shumway

## Context

The current Video Producer Skill 2.0 trusts all LLM-generated screenshots and assets without verification. This creates two classes of failures:

1. **Hallucination** — screenshot shows feature X but storyboard says Y (LLM contradicts itself)
2. **Quality Degradation** — image is noisy, compressed, misaligned, or has wrong resolution

Without validation, these errors propagate directly into the final video. The user either accepts poor output or recreates the entire job (expensive).

### Current State
- Screenshots generated by LLM storyboard generator (Anthropic Claude or local Ollama)
- No verification before rendering
- No contradiction checking (storyboard scene description vs actual screenshot)
- No artifact detection (compression, aliasing, broken layouts)
- No resolution/colorspace validation

### Decision Drivers

**Thesis:** "Trust the LLM"  
- Faster production (skip validation step)
- Simpler code path
- Assumption: good LLM → good screenshots

**Antithesis:** "Validate Everything"  
- Cost: every scene delays on validation
- Complexity: vision model calls for every asset
- Overhead: 10–20% slower production

**Synthesis:** **Lightweight Fail-Closed Validation**
- Reject only flagrant errors (contradictions, severe artifacts)
- Use efficient vision model (Claude's vision, not separate ensemble)
- Fail-closed: invalid asset → scene escalation, not silent skip
- Audit logged for GDPR + operator review

## Decision

Implement **8-point Input Validation Pipeline** (fail-closed, LDD-gated):

### Validation Checks (in order)

1. **File Integrity**
   - ✅ Screenshot file exists and is readable (PNG/JPG/WebP, <100MB)
   - ❌ If missing/corrupted → FAIL_MISSING, escalate

2. **Resolution Validation**
   - ✅ Minimum: 720p (1280×720)
   - ✅ Maximum: 4K (3840×2160)
   - ✅ Recommended: 1080p–2160p (per scene type)
   - ❌ If <720p → FAIL_RESOLUTION_TOO_LOW, escalate
   - ❌ If >4K → FAIL_RESOLUTION_TOO_HIGH, warn but allow (downscale)

3. **Colorspace Detection**
   - ✅ Detect from EXIF metadata or analyze histogram
   - ✅ Supported: sRGB, BT.709, Adobe RGB, DCI-P3
   - ❌ If unknown/undetected → assume sRGB (default)
   - ❌ If multiple color profiles detected (corrupted file) → FAIL_COLORSPACE_AMBIGUOUS, escalate

4. **Contradiction Detection** (Vision Model)
   - ✅ Feed screenshot + storyboard scene description to Claude's vision API
   - ✅ Prompt: "Does this screenshot match the described scene? List contradictions."
   - ✅ Expected: "Yes, matches" or "Minor differences: [list]"
   - ❌ If major contradictions: FAIL_CONTRADICTS_STORYBOARD, escalate
   - ❌ If LLM confidence low: WARN_LOW_CONFIDENCE, allow with note

5. **Artifact Detection** (Statistical Analysis)
   - ✅ Histogram analysis: check for blown highlights, crushed blacks, unusual distribution
   - ✅ Edge detection: look for aliasing artifacts (high-frequency noise)
   - ✅ Compression analysis: JPEG quality guess (if applicable)
   - ❌ If evidence of extreme compression/artifacts: WARN_HIGH_ARTIFACTS, allow but log
   - ❌ If watermark detected: FAIL_WATERMARK_DETECTED, escalate (user content protection)

6. **Layout Validation** (Spatial Coherence)
   - ✅ Check for visible UI elements (buttons, text, images aligned)
   - ✅ Verify no broken/overlapping elements
   - ✅ Detect if text is readable (OCR confidence >0.8)
   - ❌ If severe layout issues: FAIL_LAYOUT_BROKEN, escalate

7. **Scene-Specific Validation**
   - ✅ **Title scene:** background image exists, text area clear
   - ✅ **Narration scene:** screenshot shows relevant content (not blank)
   - ✅ **Screenshot scene:** shows actual UI (not AI-generated gibberish)
   - ✅ **Animation scene:** image suitable for motion graphics (not too detailed)

8. **Consistency Check** (vs Previous Scenes)
   - ✅ Compare with previous scene's colors/style
   - ✅ Detect jarring transitions (color space mismatch, sudden brightness jump)
   - ❌ If severe inconsistency: WARN_STYLE_CHANGE, note for color processing stage

### Failure Modes

| Result | Action | Audit Event | User Experience |
|---|---|---|---|
| **PASS** | Proceed to rendering | `asset_validation_passed` | Normal production |
| **WARN** | Proceed, log warning | `asset_validation_warned` | Production continues, metric tracked |
| **FAIL_CRITICAL** | Escalate scene, auto-retry | `asset_validation_failed_critical` | Console shows "Scene X needs review" |
| **FAIL_UNRECOVERABLE** | Reject entire job | `asset_validation_failed_unrecoverable` | User notified, job aborted |

### Data Model

```python
@dataclass(frozen=True)
class AssetValidationResult:
    """Immutable validation outcome for a screenshot asset."""
    asset_id: str
    scene_id: str
    job_id: str
    status: Literal["pass", "warn", "fail"]
    checks: List[ValidationCheck]  # each check result
    
    # Overall result
    overall_confidence: float  # 0–1, whether the asset is usable
    fallback_action: Literal["proceed", "retry_llm", "manual_review", "reject"]
    
    timestamp: datetime
    tenant_id: str

@dataclass(frozen=True)
class ValidationCheck:
    """Single validation check result."""
    check_type: str  # "file_integrity", "resolution", "contradiction", etc.
    passed: bool
    severity: Literal["info", "warn", "fail"]
    message: str
    metadata: Dict[str, Any]  # check-specific data (e.g., actual_resolution, confidence_score)
```

### Conceptual Level

**Principle:** "Trust but verify" — LLM is powerful but fallible; validation catches hallucinations without blocking production.

**Mental Model:** Input validation is a **gate**, not a bottleneck. Most assets pass; edge cases are caught and escalated. The system learns from escalations (feedback loop integrates in Phase 2).

### Structural Level

**Architecture:**
- InputValidator Skill (phase 1 core, replaces ad-hoc checks)
- Sits between Storyboard Generation and Scene Rendering
- Feeds into Color Processing Pipeline and Encoding decisions (Phase 2)
- Emits audit events + validation confidence scores

**Integration Points:**
- Storyboard Generator (produces screenshots) → InputValidator → Scene Renderer
- User Feedback Loop (Phase 2) reads validation results, tunes LLM prompts
- Observability Dashboard (Phase 3) shows validation status per scene

**Fail-Closed Design:**
- Invalid asset → escalate, don't render anyway
- Validation timeout (>10s) → fail-closed (reject asset)
- Vision API unavailable → fail-closed (wait, don't skip check)

### Implementation Level

**InputValidator Skill (new file: `core/skills/video_producer_skill/input_validator.py`):**

```python
class InputValidatorSkill:
    """Validates screenshot assets before video rendering."""
    
    async def validate_asset(
        self,
        asset_path: str,
        scene_metadata: dict,
        job_context: dict
    ) -> AssetValidationResult:
        """
        Run all 8 validation checks on a screenshot asset.
        Returns: AssetValidationResult with pass/warn/fail status.
        """
        result = AssetValidationResult(
            asset_id=generate_id(),
            scene_id=scene_metadata["id"],
            job_id=job_context["job_id"],
            status="pending",
            checks=[],
            overall_confidence=0.0,
            fallback_action="pending",
            timestamp=datetime.now(timezone.utc),
            tenant_id=job_context["tenant_id"]
        )
        
        # 1. File Integrity
        check_1 = self._check_file_integrity(asset_path)
        result.checks.append(check_1)
        if check_1.severity == "fail":
            return result.with_status("fail", action="reject")
        
        # 2. Resolution Validation
        check_2 = self._check_resolution(asset_path)
        result.checks.append(check_2)
        if check_2.passed and check_2.metadata.get("resolution") == "upscaled":
            check_2.severity = "warn"  # log warning but proceed
        
        # 3. Colorspace Detection
        check_3 = self._detect_colorspace(asset_path)
        result.checks.append(check_3)
        
        # 4. Contradiction Detection (Vision API)
        check_4 = await self._check_contradiction(
            asset_path,
            scene_metadata["description"]
        )
        result.checks.append(check_4)
        if check_4.severity == "fail":
            return result.with_status("fail", action="retry_llm")
        
        # 5. Artifact Detection
        check_5 = self._detect_artifacts(asset_path)
        result.checks.append(check_5)
        
        # 6. Layout Validation (Vision API)
        check_6 = await self._validate_layout(asset_path)
        result.checks.append(check_6)
        
        # 7. Scene-Specific Validation
        check_7 = await self._validate_scene_specific(
            asset_path,
            scene_metadata["type"]  # "title", "narration", etc.
        )
        result.checks.append(check_7)
        
        # 8. Consistency Check (vs Previous Scene)
        prev_asset = self._get_previous_scene_asset(job_context)
        if prev_asset:
            check_8 = self._check_consistency(asset_path, prev_asset)
            result.checks.append(check_8)
        
        # Compute overall status
        critical_failures = [c for c in result.checks if c.severity == "fail"]
        if critical_failures:
            result.status = "fail"
            result.fallback_action = "retry_llm"
            result.overall_confidence = 0.3
        else:
            warnings = [c for c in result.checks if c.severity == "warn"]
            result.status = "warn" if warnings else "pass"
            result.overall_confidence = 0.95 - (len(warnings) * 0.05)
            result.fallback_action = "proceed"
        
        # Audit Log
        self.audit_backend.write_event("asset_validation", {
            "asset_id": result.asset_id,
            "status": result.status,
            "overall_confidence": result.overall_confidence,
            "checks_summary": {
                "passed": sum(1 for c in result.checks if c.passed),
                "warned": sum(1 for c in result.checks if c.severity == "warn"),
                "failed": sum(1 for c in result.checks if c.severity == "fail"),
            },
            "job_id": job_context["job_id"],
            "tenant_id": job_context["tenant_id"],
        })
        
        return result
```

### Testing

**Unit Tests** (each check in isolation):
- `test_file_integrity_missing` → FAIL
- `test_file_integrity_corrupted` → FAIL
- `test_resolution_too_low_640p` → FAIL
- `test_resolution_4k_upscaled` → WARN
- `test_contradiction_major` → FAIL, action=retry_llm
- `test_contradiction_minor` → WARN
- `test_artifact_high_compression` → WARN
- `test_layout_broken` → FAIL
- `test_consistency_color_jump` → WARN

**E2E Tests** (full validation pipeline):
- `test_valid_screenshot_passes_all` → PASS
- `test_invalid_screenshot_fails_critical` → FAIL, job escalated
- `test_warning_aggregate_proceeds` → WARN, proceeds with audit logged

**LDD Metrics:**
- Precision: false-positive rate <5% (don't reject good assets)
- Recall: catch 90%+ of real hallucinations
- Performance: validation latency <5s per asset (fail-closed timeout at 10s)

### Deployment

**Phase 1 Rollout:**
- Week 1: InputValidator Skill implementation + tests
- Week 2: Integration into VideoProducerSkill (Maestro)
- Integration with Console panel: job status shows "Validating" phase
- Operator Dashboard: per-job validation summary (# of warnings/failures)

**Canary:** First 5 jobs run with validation; if success rate >95%, expand to 100%

## Consequences

### Benefits
- ✅ Catches LLM hallucinations before rendering (saves rendering time)
- ✅ Audit trail shows every validation decision (GDPR compliance)
- ✅ User feedback on "why was my asset rejected" (transparency)
- ✅ Learning loop can optimize LLM prompts (Phase 2)

### Costs
- ❌ +5–10s per scene (vision model API calls)
- ❌ Vision API quota usage (costs $)
- ❌ Complexity (8 checks, multiple failure modes)

### Mitigation
- Vision API calls cached where possible
- Parallel validation (multiple scenes in parallel)
- Operator can disable validation for trusted sources (override flag)
